# TrendMe ML

ML-сервис отвечает только за подготовку признаков, обучение, оценку, инференс и объяснение решения классификатора. Он не выполняет открытый поиск и не хранит источники: это ответственность Django-сервиса `trendme`.

## Методология

Модель — интерпретируемая логистическая регрессия. Она отделяет слабые сигналы (класс `1`) от зрелых технологий (класс `0`) по десяти признакам:

- маркеры зарождения, зрелости и маркетингового хайпа в тексте;
- доверенность и ранний тип источника;
- наличие патента и инвестиций;
- свежесть публикации, низкая распространённость и динамика упоминаний.

Для каждого предсказания `/predict` возвращает вероятность, решение по порогу и вклад каждого признака. Поэтому Django может показать пользователю, почему кандидат получил именно такую оценку. Пороги: слабый сигнал — `0.50`, высокая уверенность — `0.75`.

## Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python train.py --save --report
.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8001
```

Проверка: `GET /health`. Swagger-контракт: `GET /docs`.

## Обучение и отчёт

```bash
python train.py --weak data/100_слабых_технологических_сигналов_сентябрь_2026.xlsx --mature data/mature_technologies.csv --save --report
```

Команда формирует `artifacts/weak_signal_model.joblib` и `artifacts/model_report.json` с Accuracy, Precision, Recall и F1 для 5-fold кросс-валидации и отложенной выборки.

Текущие файлы `weak` и `mature` уже разделены по классам, поэтому локальная метрика характеризует только этот контрольный набор и не является заменой независимой проверки. Для соответствия ТЗ итоговый отчёт необходимо построить на закрытой валидационной выборке организаторов без её использования в обучении.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют корректность дат, обработку некорректной обучающей выборки, объяснимое предсказание и контракты методов сервиса.
